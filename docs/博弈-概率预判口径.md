# 博弈：概率预判与混合策略（口径与实测）

> 起因：用户提出"博弈很多时候是在赌博——我方克制对面时，对面可能换也可能不换；
> 我可以预判换宠出克制技能、预判不换打伤害，或者白嫖强化。有没有能表示这种模糊性的东西？"
>
> 本文记录：① 形式化选择（为什么不是模糊决策）；② 落地实现与引擎对拍结论；
> ③ **实测结果（含负结果）**；④ 下一步建议。

## 0. 结论速览

| 项 | 结果 |
|---|---|
| 这类"赌"的合适形式化 | **信念 + 期望值**（Bayesian EV）+ **混合策略/纳什无差异频率**；**不是** fuzzy logic |
| 赌注有多大（E0，300 局 / 13390 决策点） | 对手换人率 **23.5%**；"它换/不换"要求不同技能的决策点 **23.4%**；押错方向平均损失 **7.3%** 最大生命（p90 29.9%，最高一条命） |
| 实现 | `backend/sim/belief.py`（概率）+ `backend/sim/ev.py`（收益矩阵/期望值/采样），接入 `RuleAgentV2`（**默认关闭**，`SpriteStrategy.ev_decide`） |
| 收益矩阵对拍 | 预估伤害与引擎真实结算逐格一致（容差只留取整）；应对三角、换人先手、幻影斩杀都对拍过 |
| **期望值层 vs 旧启发式** | 2000 局配对：**0.476 [0.454, 0.498] → 略低于旧启发式**（CI 不含 0.5） |
| **参数校准**（`tune_ev_params.py`） | 搜索集能到 0.565、3 个复核 seed 上 0.530，但换 6 个全新 seed 只有 **0.453**（同种子下默认参数 0.476）→ **过拟合搜索种子，校准失败** |
| **软最大化混合** | **有害**：剥削者视角胜率 T=0.05 → 0.500、T=0.10 → 0.348、T=0.35 → **0.255**；T=0 时剥削者也占不到便宜 → 混合只付代价 |
| 落地决定 | 期望值层**默认关闭**（保留为显式实验开关 + 可校准），混合默认 T=0；专家仍用旧启发式 |
| **度量地基（§4f，本轮）** | 引擎**跨进程逐位确定**（探针指纹一致 ×3）；漂移全部来自协议：`PYTHONHASHSEED` 未钉 / 阵容抽取未播种 / 门控随机数流随 worker 顺序变，**外加一处 A/B 设计错误**（旧 `eval_expert_change` 量的是先手/侧别偏差，不是规则差异）→ 全部已修 |
| **修正后的专家层收益** | 三条蒸馏规则合并 **0.514 [0.501,0.526]**（同局对照 3999 局 × 2 组 seed）；**单条规则分辨不出来**（±1.5 点内）；防御层单独看略负（0.489） |

## 1. 为什么不是"模糊决策"

我们的引擎是**完全信息**（`encoder.py` 默认不遮对手板凳，双方都能看到 6 只的全部状态），
所以这不是隐藏信息/POMDP 问题，而是**每回合同时出招的同时行动博弈**（与猜拳同构）。
"模糊决策"（fuzzy logic）建模的是**界限不清**（"血量偏低"这种隶属度），不是**策略不确定**；
对策略不确定，标准工具是概率 + 博弈论：

| 形式化 | 用途 | 先例 |
|---|---|---|
| 信念 + 期望值（expectimax） | 有概率就按概率加权取最大 | Pokémon 天梯 bot（Showdown 社区、PokéAgent Challenge）、本仓 `service/advisor.py` 的 PIMC（`weights` 接口早有，一直没有数据源） |
| 混合策略 / 无差异频率（CFR、regret matching） | 让对手"换与不换期望相同"，自己不可被剥削 | 扑克 CFR（Libratus/Pluribus）；社区"该 3-bet 30%" |
| 风险调整（maximin / 安全打法 / 风险优势） | 期望接近时选下限高的 | 哈萨尼-塞尔腾风险优势 |
| level-k / 认知层级 | 对手是人、会想到第几层 | 本地 wiki 6 份《对手档案》带 S/A+/B+/D+ "博弈先读"评级 |
| 策略池 + PSRO/联盟 | 对手风格未知时的正解 | AlphaStar league、PSRO（**本项目最缺**：自博弈对手 = 当前网络自己） |

硬阈值软化（sigmoid 替代 `hp < 0.35`）算工程改良，不算形式化框架。

## 2. 表示：信念 × 收益矩阵

- **行** = 我的候选动作（可用技能 / 安全替补 / 聚能；道具与首领化由 `item_policy` 先处理）；
- **列** = 对手行为假设（`attack / defense / status / switch / gather`，**粗粒度是刻意的**：
  精确预测具体技能不可能，而博弈维度就是技能类别 + 换人）；
- **格** = 本回合战术价值
  `(它掉血率 − 我掉血率) + kill_bonus·(它倒 − 我倒) + 强化/能量收益 − 应对/冷却/进场/换人对位项`
  （各自按自己的最大生命归一化，可跨行比较）。

信念（`belief.py`，全部特征都是引擎可算的事实，权重集中在一个 dataclass，可校准）：

| 信号 | 方向 | wiki 佐证 |
|---|---|---|
| 我方能一击斩杀它 / 它被 tick 死 | P(换) ↑ | — |
| 它能量打不出任何攻击 | P(换) ↑ | 《04-换人与脱战》"对方无能量→大概率聚能或换人" |
| 它被我方属性克制 | P(换) ↑ | 同上"对方被克制→可能换人" |
| 它刚换上过 | P(换) ↓ | 换人有 tempo 成本 |
| 它带可用防御技且我威胁大 | 防御列 ↑ | 《02-应对机制》防御技反制攻击 |
| 它带强化技且我威胁小 | 状态列 ↑ | 《04》换人清增益 → 叠 Buff 慎换 |

## 3. 对拍引擎时发现的机制（写进模型的事实）

1. **应对判定是双方技能字段的纯函数**：`SkillResolver.resolve_counter(atk, def)` 看 `def.counter`
   是否匹配 `atk` 的类别（技能 JSON 的 `counter` ∈ 无/攻击/防御/状态，594 个技能里 129 个带应对）。
   严格三角：防御技反制攻击、攻击技反制状态、状态技反制防御。
2. **应对与出手顺序无关**，但一旦有任一方应对成立，**A 方强制先出手且双方 `is_first=True`**
   （`battle.py:1103`；这是引擎实现细节，wiki 未描述）。
3. **被应对方那一手会被"反击"成应对方技能的基础伤害**（实测：偷袭 vs 状态技 = 基础×3 **+ 基础**一次）。
   wiki 对 应对状态 只写了"伤害最大化，打出数倍伤害"，**没写这条额外一击** → 属待核对的口径/实现问题。
4. **换人先于技能**（`battle.py:1056`）→ 我换人时吃伤害的是换上来的那只（含印记进场伤害）。
5. **幻影斩杀**：对手先手且这一击能杀我时，我这一手的伤害必须算 0（否则模型会高估）。
6. 估算伤害必须把真实出手顺序传进 `SkillUse(is_first=…)`——印记倍率就吃它。

## 4. 实测（工具与口径）

- `native/tools/measure_prediction_stakes.py` — 赌注度量（E0）。
- `native/tools/eval_prediction_mix.py` — 验收：成对交替执 A/B，300 局/组；
  "剥削者" = `RuleAgentV2` 子类，注入"我算准你 T=0 会出哪类"的退化信念（完全信息下它算得出），
  其余流程（斩杀/保命/道具）完全复用 → 衡量的是**可预测性**，不是绝对棋力。

| 组 | 胜率（被评估方视角） | 读法 |
|---|---|---|
| 期望值 vs 旧启发式 | 0.463 [0.403, 0.524] | **无可测提升**（CI 含 0.5） |
| 期望值 T=0 镜像 | 0.473 [0.411, 0.536] | 基线噪声带 ≈ ±0.06（n=300） |
| 剥削者 vs 确定性 T=0 | 0.481 [0.418, 0.545] | 剥削者没占到便宜 |
| 剥削者 vs 混合 T=0.05 | 0.500 [0.439, 0.561] | 无害 |
| 剥削者 vs 混合 T=0.10 | 0.348 [0.289, 0.406] | 明显有害 |
| 剥削者 vs 混合 T=0.35 | **0.255 [0.202, 0.307]** | 严重有害 |

**混合为什么有害**：softmax(T) 在 EV 差 0.2 时仍给劣招 ~36%（T=0.35）的概率；
而本博弈的收益矩阵不是对称零和猜拳——**按自己期望值的软分布出招 ≈ 主动打劣手**。
理论上混合只应在**无差异点**（两动作 EV 相等）才值得，那种情形下没有 EV 损失：
我们用 `softmax_pick(T=0)` 的"完全平局随机化"覆盖了它。**故默认 T=0**。

## 4b. 参数校准（`native/tools/tune_ev_params.py`）——也失败了，但要看清失败方式

方法：局部扰动 + 逐轮淘汰（半径 0.35→0.09→0.04，局数 100→200→400），
目标 = 对旧启发式的配对胜率；**判定规则事先定好**：未参与搜索的 seed 上 CI 下界 > 0.5 才算赢。

| 阶段 | 结果 |
|---|---|
| EV 常数（8 个）搜索集 | 最优 0.492（n=329） |
| ↳ 3 个复核 seed（7/99/2027） | 0.523 [0.487, 0.559]（下界仍 < 0.5） |
| 再叠加信念先验（7 个）搜索集 | 最优 **0.565**（n=317） |
| ↳ 同 3 个复核 seed | 0.530 [0.493, 0.566] |
| ↳ **6 个全新 seed（n≈2000，高统计力）** | **0.453 [0.431, 0.475]（显著低于 0.5）** |
| **同 6 个 seed 上的手设默认参数** | **0.476 [0.454, 0.498]** |

结论与教训：

1. **校准失败于"种子过拟合"**：在 3 个复核 seed 上 0.530 看着像"提升"，换 6 个 seed 就掉到 0.453，
   **比手设默认还差 2.3 个点**。回合制对局的阵容/克制方差很大，单 seed（甚至 3 seed）的胜率
   不足以做选择依据 → 以后调参必须**多 seed 搜索**（搜索集本身就是多 seed 加权），不能只在
   单个 seed 上排序。
2. 校准器把**我手设的两个"未来价值"项压到 0**：`switch_position_weight`（换人对位收益）
   与 `status_tempo_penalty`（对方状态技的隐性代价）——说明这两个我拍脑袋加的项是负贡献。
   相反 **`w_lethal`（能斩杀它）与 `w_tick_doom`（它被 tick 死）是该管用信号**（权重收敛到 2.1/2.6），
   而 wiki 推来的 `w_countered`（被克制→换人）与 `w_low_energy`（无能量→换人）被压到 ≈0。
3. 行为诊断：EV 层与旧启发式的**动作类型分布几乎一样**（技能 30% vs 28%、换人 11% vs 10%、
   聚能 9% vs 12%），差别只在"选哪一招/打谁"——所以这不是"EV 太保守/太激进"，而是
   **一格棋的解析式估值（单回合、无搜索）精度不够**，压不过社区经验磨出来的阈值。
4. 落地：**`ev_decide` 默认改为 False**（旧启发式仍是出厂专家），EV 层保留为显式开关
   （`SpriteStrategy(ev_decide=True)`，或把 `checkpoints/ev_tuning.json` 的 `best_cfg` 传给
   `RuleAgentV2(ev_params=…)`）。想继续走这条路，方向应是"只在预判会改打法的决策点覆盖"
   （§5-2）或把估值换成**搜索式**（rollout），而不是继续调这 15 个常数。

## 4c. 决策审计与"蒸馏"（人当教师 → 改规则）

流程（`native/tools/audit_ruleagent_decisions.py`）：记录每个决策点的可见状态、选择、
候选打分与**事后结果**，自动标出可疑模式；人工复核后把经验写成规则；再用
`native/tools/eval_expert_change.py`（配对、交替执 A/B）验收。

80 局 / 5216 个决策点的审计结论（旧启发式路径）：

| 可疑模式 | 占比 | 教师判断 |
|---|---|---|
| `switch_wasted`（我换人而对面没换） | 11.1% | **一半是真错**：低血 + **能量打不出招**时会在残血换位规则里空转，同一只精灵"换出去又换回来" |
| `doomed_stayed` | 9.7% | **基本假阳性**：全是镜像同血同能量的对称局面，攻击才是对的 |
| `energy_burnout` | 3.5% | 多为假阳性（对手中途换人导致打分过期） |
| `missed_kill` | 2.8% | **真错**：能一击斩杀但"我出手前会死"时一律撤人，**完全不算交换价值** |
| `overkill` | 2.0% | 多为估值误差（预估≥斩杀线、实际差 6%），非决策错 |
| `buff_under_threat` / `defense_wasted` | ≈0 | 无问题 |

据此落了两条规则（都写进 `agent_v2.py`，测试在 `backend/tests/test_agent_v2_distilled.py`）：

1. **交换价值**（`SpriteStrategy.trade_margin`，默认 0.15）：能斩杀但会被先手打死时，
   只有"用更残的换更健康的"（血量比例差 ≥0.15）才吃一换一，`preserve` 精灵血量 >0.35 时除外。
2. **防空转**（`SpriteStrategy.anti_switch_loop`，默认 True）：刚换上来的那只不参与"残血换位"。
3. **防御层**（`SpriteStrategy.defend_threshold`，默认 0.30）：会被重击且打不死它时举盾
   （§4e 引入，单独看略负、合并无差异，见 §4f-④）。

**配对胜率验收（旧工具口径 —— 已作废，见 §4f）**：

| 改动 | 局数 | 新口径胜率 |
|---|---|---|
| 交换价值 | 1200（3 seed） | ~~0.500 [0.469,0.531]~~ |
| 防空转 | 1200（3 seed）→ 4000（5 seed） | ~~0.523 → 0.509 [0.492,0.526]~~ |

⚠️ 这两行是 `eval_expert_change.py` 旧版报出的数：它把规则开关设在**模块级常量**上，
一局里两侧读到同一个值，只能比较"整局新口径 vs 整局旧口径"两个镜像 → **量到的是先手/侧别
偏差，不是规则差异**（所以永远在 0.5 附近）。修正后的同局对照结果见 §4f-④。

**结论（重要）**：**手写规则层的单条改动都在噪声内**，三条合起来才有约 +1 点（§4f-④，
同局配对 8000 局、两组 seed 一致）。真正大幅度动过胜率的只有**机制级修复**（道具口径：
进化之力使用率 30%→84%；首领形态/队内同编号/幻影斩杀/先手值这些"把不可能变可能"的修正）。
→ 想继续提升，杠杆在**数据规模与质量**（P3：10000 局 BC → 预训练 → 自博弈）或
**搜索/联盟**（训练侧），不在继续手写规则。

测量口径提醒：`--max-turns 40~60` 下有 **20~30% 平局**，只看决出局会稀释信号；
训练门控的口径是**平局记 0.5**（`eval_score_for_candidate`），本仓的 A/B 工具都同时给两个数。



## 4d. 净收益：当前专家 vs **会话改动前**的专家

基线 = `git HEAD:backend/sim/agent_v2.py`（本会话开始时该文件未改动）。工具
`native/tools/eval_vs_previous_agent.py` 运行时从 git 取源码 exec 成模块（不落临时文件）；
两队阵容/道具完全相同、交替执 A/B、`PYTHONHASHSEED=0`。

| 对比 | 局数 | 结果 |
|---|---|---|
| **当前专家 vs 会话前专家** | 3000（5 seed） | **0.509 [0.489, 0.528]**（1293 胜 / 1248 负 / 464 平） |
| 只修「进化之力不限回合」（单行） vs 会话前 | 2000（4 seed） | 0.507 [0.482, 0.532] |
| 交换价值 / 防空转（§4c） | 1200 / 4000 | 0.500 / 0.509 [0.492, 0.526] |

**净收益 = +0.9 个点 → 统计上打平**（CI 下界 < 0.5）。本会话对专家决策的所有改动
（道具口径、战术预判、交换价值、防空转、期望值层）**在同分布自对弈里没有可测的强度提升**；
可见的变化是**行为风格**：换人率 13.4%（旧 17.4%）、聚能 26%（旧 24%）——更少无谓换人。

为什么：① 这些改动的价值是**正确性/稳健性**（首领化从"70% 的首领队整局变不了身"修到 84% 使用率），
但变身收益被阵容克制与 RNG 淹没；② 回合制对局的决定性因素在**阵容/克制/先手**，不在单只的一次判断；
③ 专家本来就是社区阈值磨出来的不错基线，边际改动自然小。

**固定阵容口径（`native/tools/eval_fixed_rosters.py`，每套阵容打满、两侧交替）**：

工具设计要点：每套阵容的 `Item` 必须 `deepcopy`（道具是可变对象，`uses` 会跨局累积——
不修的话第一局用掉进化之力后，后面 49 局道具都是"已用"状态，**系统性压制新版优势**，
因为新版的道具使用率是老版的三倍。这个 bug 一修，结论立刻翻转）。

| 阵容批次 | 1000 局胜率（旧口径：阵容未播种，**数字不可复现**） | 均值 |
|---|---|---|
| seed 2026（20 套） | 0.612 / 0.564 / 0.573 | **0.583** |
| seed 777（20 套） | 0.522 / 0.509 | **0.516** |
| 两批合计（4776 决出局） | **0.555 [0.545,0.565]** | — |
| 对照：3000 局**随机**阵容 | 0.506 [0.486,0.525] | — |

**结构（比总胜率更有信息量）**：20 套阵容里只有 **3–6 套由 agent 版本决定胜负**
（且往往是一边倒 50:0 / 0:50 的干净横扫），其余阵容里胜负由"哪一侧/随机数"决定
（精确 25:25，与版本无关）；还有一套是纯平局镜像（50 平）。
→ 改动的价值集中在少数阵容类型上，**抽到哪批阵容会显著改变总胜率**（0.52 vs 0.58）。

**度量口径的残留问题 → 已定位并修复（§4f）**：重复之间差 5 个点的原因**不是引擎**，
而是这个工具抽阵容用的是**未播种的全局 `random`**（进程启动时由 OS 熵播种）——
同一命令每次抽到不同阵容。修好后同命令两次跑出**逐位相同**的数字：

| 阵容批次（修复后，同命令两次完全一致） | 1000 局胜率 | 胜负平 |
|---|---|---|
| seed 2026（20 套，混合 meta/随机） | **0.639 [0.608,0.670]** | 575/325/100 |
| seed 777 | **0.535 [0.504,0.566]** | 535/465/0 |
| seed 1001 | **0.645 [0.615,0.675]** | 616/339/45 |
| seed 4242 | **0.576 [0.545,0.606]** | 571/421/8 |

四套均值 ≈ **0.599**，每套 1000 局（CI ±3 点），四套的 CI 下界都 > 0.5。
→ **在"非对称阵容"口径下当前专家确实更强（≈+10 点）**；而"镜像阵容"口径
（`eval_vs_previous_agent.py`，3000 局随机阵容）只有 **0.509 [0.489,0.528]**。
两个口径测的不是同一件事：前者是**实战对位**（两队不同、克制关系真实存在），
后者是**镜像决策质量**（两队相同，胜负大量由先手/随机数决定 → 效果被稀释）。
报告数字时必须说清用的是哪个口径。


- 运行间不确定性：见 §4f（三处协议漏洞：hash seed / 阵容未播种 / 门控随机数流）。
- **平局率 15%**（3000 局 464 平）→ 只看胜负会稀释信号；精细比较应带血量/力倒数裁决分。

**结论**：专家层到此为止（正确性修好、风格更干净）；**强度杠杆不在专家层**。
这条结论现有四组独立测量支撑（EV 层、调参、蒸馏规则、整体净收益）。

## 4e. 对照职业复盘找到的"漏掉的关键变量"：防御/应对层

**做法**：读三份洛神杯 B 组复盘（`wiki/对局记录/单局记录/*.md`，源自 B站解说 BV1jX9fB8Eax 等），
提取"胜负决定因素"，再**在本引擎里逐条量化我们的覆盖度**。

职业复盘反复出现的胜负因素：① **应对先读**（一场 × 小辞 2:2 vs 鬼叔 0:3，直接被称为"制胜基础"；
另一场灵羽骑士 T10-T11 连续两次读中状态技）；② **心力管理**（"叠 5 层中毒值不了 1 心"、
特性双刃剑 3心→2心→0心 终结比赛）；③ **出手权**（速度线表 + 先手技；22 回合里出手顺序被
应对/迅捷/先手/加速改了 9 次）；④ **补刀纪律**（"打至 5% 却聚能"→ 被反杀）；⑤ **印记运营**
（叠层→引爆；星陨换人不消失）。

**量化结果（120 局 / 8416 个决策点）**：

| 项 | 数据 |
|---|---|
| 配装里非攻击技（防御/状态）占比 | 274 只的最优配装 **46%**；40 支 meta 站队 952 槽 **47%** |
| 其中带应对字段（counter≠无） | 最优配装 **32.4%**；meta 站队 **30.4%** |
| **专家实际出招** | 攻击 **60.5%**、聚能 23.4%、换人 13.5%、**状态 0.0%、防御 0.0%** |
| 我侧星陨印记平均层数 | **0.02**（职业复盘里印记是胜负核心） |
| 我方有"应对机会"的决策点 | **22.5%**（可用技能里有一个正好反制它实际出的类别） |

**结论：我们装备着整套博弈层，却从不使用它——自对弈退化成了"换血赛"。**
这也解释了为什么之前所有改动（EV 层、调参、交换价值、防空转）都测不出收益：
在一个双方都不防御/不叠印记的退化均衡里，攻击就是最优解。

**决定性实验**（临时脚本，300 局配对、交替执 A/B；**口径：固定对手 vs 待测专家**）：
写一个只会"被威胁就防御"的粗糙对手（判据 `对手最强一击 ≥ 30% 当前血量` 且有可用防御技），
其余全用出厂专家逻辑：

| 对手 | 对出厂专家胜率 | 读法 |
|---|---|---|
| **防御型对手** | **0.571 [0.511,0.631]** | 出厂专家被这一层**打穿**（CI 下界 > 0.5） |
| 应对型对手（按信念挑 counter 技） | 0.475 [0.415,0.536] | 我这版读太粗，没占到便宜（后续要用更好的预测） |

**把防御补进专家**（`SpriteStrategy.defend_threshold = 0.30`，判据照抄那个对手、相对**当前**血量）：

| 变体 | 结果 |
|---|---|
| 防御放在"撤人"**之后** | 对手胜率 0.571 → 0.545（只关掉一半） |
| 防御放在"撤人"**之前**（最终实现） | 对手胜率 → ~~0.500 [0.439,0.561]（漏洞关闭）；自对弈 A/B 0.536 [0.512,0.560]~~ |

⚠️ **上面这一行的数字不可采信**：那是哈希种子未钉住时测的，而且后半个（"自对弈 A/B 0.536"）
用的是坏工具（模块级常量 A/B → 量到侧别偏差，见 §4f-③）。**修正后的复测**：

| 检查（可复现口径） | 局数 | 结果 | 读法 |
|---|---|---|---|
| 同局对照 A/B（防御开/关，其余全同） | 4000 × 2 组 seed | 0.485 [0.468,0.503] / 0.492 [0.474,0.510]；合并 **0.489 [0.477,0.500]** | **略负**（防御侧每 100 局多输 ~1 局） |
| 平局记 0.5 的分数差（同上） | 8000 | **−0.042 / −0.021** | 略负 |
| 对**固定粗糙剥削者**（§4f 工具，剥削者视角） | 1000 × 2 | 防御关 0.459 → 防御开 0.469（分数 0.533 → 0.587） | 对"惩罚型"对手仍略有优势 |

**读法**：防御层**不是一个被确认的收益**——它在同局对照里略负、在固定粗糙对手面前略正。
保留为**可开关**（默认 0.30，因为它不影响三条合并后的收益，且对付"会被算准就惩罚"的对手有用），
但**不要**把它当成 §4e 原本以为的"补上关键变量就变强"。

**为什么顺序仍是关键**（机制层，未被证伪）：防御挡的是本回合的伤害；撤人却把伤害转给
换上来的那只（还吃印记进场伤害）。放在撤人之后时，真正该举盾的局面全被"恐慌换人"吃掉了。

**净收益**：当前专家 vs 会话前专家，镜像随机阵容口径 **0.509 [0.489,0.528]**（3000 局）、
非对称固定阵容口径 **0.535~0.645**（四套各 1000 局，见 §4d）。**别把净收益说成 +3.6 点。**

**下一步（本轮定位出的方向）**：
1. **用"会博弈的专家"重生成 BC 数据**（防御 16% 出招已进标签）——否则网络学不到这一层，
   而我们交付的是模型不是 agent；
2. **陪练要多样**：自对弈里双方都是同一个专家时，防御的价值天然被低估（对手只会攻击）；

## 4f. 度量地基：确定性审计（本轮，结论：引擎确定，坏的是协议）

**起因**：用户质疑"这么多轮迭代胜率都在 50 左右不可能"。查证结论：**引擎逐位确定，
漂移全部来自测量协议**，且其中一处协议错误让"单条规则的 A/B"根本测不出东西。

### ① 引擎是确定的（已证明）

`native/tools/determinism_probe.py`：同 seed 抽阵容 → 跑 20 局 → 每回合记录
（先手方、双方当前精灵血量/能量/属性修饰/效果层数/技能冷却、印记、天气）并整体取哈希。

- 同一进程内把每局重复跑两遍：**完全一致**（排除跨局状态泄漏、缓存污染）。
- 两个独立进程：**总指纹逐位相同**（`ddcbadc16aa7ae3d`）。
- 修复前两个进程指纹不同 —— 差异**不是**引擎造成的，见 ②-2。

→ 此前怀疑的 `id()` 迭代顺序、浮点加法顺序、`direct_mod_sprite_ids` 之类的猜疑**不成立**；
引擎在固定输入下是确定性的。

### ② 三处协议漏洞（都已修）

| # | 漏洞 | 后果 | 修法 |
|---|---|---|---|
| 1 | **`PYTHONHASHSEED` 未钉住**（7 个工具 + `train.py`） | 字符串哈希随机化 → `list(set(技能池))` 这类迭代顺序逐进程不同 → 配装/阵容不同 | 统一 `backend/engine/ai/determinism.py::ensure_hash_seed()`：带 `PYTHONHASHSEED=0` 重执行自己（正确处理 `python -m pkg.mod`，`ROCO_KEEP_HASH_SEED=1` 可跳过） |
| 2 | **阵容抽取用未播种的全局 `random`**（`eval_fixed_rosters.py`、探针） | 抽阵容发生在 `random.seed()` 之前 → 由 OS 熵决定，同一命令每次阵容不同（1000 局差 2–5 点） | `_random_teams(..., rng=)` 收显式 `random.Random(seed)`；工具传入 |
| 3 | **门控评估的随机数流**（`train.py` + `selfplay_worker.py`） | worker 只在启动时 seed 一次，之后按 work-stealing 顺序连续消耗随机数 → **同一模型两次门控分数不同**；且每轮门控重新抽阵容 → 训练曲线在阵容抽样方差里漂移 | 阵容套件由固定种子生成（`_eval_roster_rng()`，每次评估同一批），单局种子 = `f(局号)`（`_seed_eval_game`），与领取顺序无关 |

修完的效果：同一命令两次运行**逐位相同**（`eval_fixed_rosters` 1000 局、`eval_vs_previous_agent`
600 局、`eval_expert_change` 4000 局、探针指纹，全部复现）。

### ③ 一处协议**设计错误**：`eval_expert_change.py` 量的是侧别偏差

三个规则开关原本是**模块级常量**，而一局里两侧都是 `RuleAgentV2`、读的是同一个全局值 →
旧版"整局用新口径 vs 整局用旧口径"只能比较**两个镜像**，没有任何一局是"新口径 vs 旧口径"
的直接对抗。它的记账还把"新口径局里 B 赢"算成旧口径胜 → 报出的数字实际是**先手/侧别偏差**
（所以永远在 0.5 附近：0.500 / 0.509 / 0.505 / 0.519 / 0.482 …）。

**修法**：开关改为**逐策略实例**字段（`SpriteStrategy.trade_margin / anti_switch_loop /
defend_threshold`），A/B 工具改成**同局对照**：同一套阵容、同一批随机数，一侧新口径、
另一侧旧口径，第二局交换两侧。

### ④ 修正后的结果（同局对照，3999 局/组 × 两组独立 seed）

| 规则 | seed 2026,7,99 | seed 11,222,3333 | 合并 | 平局记 0.5 的分数 Δ |
|---|---|---|---|---|
| trade 交换价值 | 0.507 [0.488,0.525] | — | — | +0.012 |
| antiloop 防空转 | 0.508 [0.490,0.526] | — | — | +0.022 |
| defend 防御层 | 0.485 [0.468,0.503] | 0.492 [0.474,0.510] | **0.489 [0.477,0.500]** | −0.042 / −0.021 |
| trade+antiloop | 0.513 [0.494,0.531] | 0.506 [0.488,0.525] | 0.510 [0.497,0.522] | +0.035 / +0.023 |
| **三条一起（当前默认）** | **0.512 [0.495,0.530]** | **0.515 [0.497,0.532]** | **0.514 [0.501,0.526]** | +0.034 / +0.046 |

- **单条规则都在 ±1.5 点内**（防御层单独看略负）；**两条/三条合起来约 +1.0~1.4 点**，
  两组不相交的 seed 一致、8000 局合并后 CI 下界 > 0.5 → 这是本会话唯一在"配对 + 同局 +
  可复现"口径下站住的专家层正收益。
- 结论不变但更精确：**专家层的边际收益只有 ~+1 点量级**，需要 4000 局以上的同局对照才分辨得出来；
  之前那些"确认/中性"的判断都是坏工具给的。

## 5. 下一步建议（按性价比）

**先把结论口径说清楚**（§4f 之后）：
- "专家层饱和"依然成立，精确表述是**边际收益 ~+1 点**（三条蒸馏规则合并，同局对照 8000 局，

- 只有"把不可能变可能"的机制级修复（道具口径、首领形态、队内同编号、幻影斩杀、先手值）
  是大幅度的收益，其余都在 ±1~2 点的量级。
- **一切新改动都必须用同局对照（`eval_expert_change.py --ab`，≥4000 局）或固定对手口径；
  镜像随机阵容口径（0.509）只适合看"整体方向"，非对称固定阵容口径（0.599）适合看"实战分位"。**


0. **用（机制修正过的）专家重生成 BC 数据**（P3）：标签质量比"多一张防御牌"更重要——本轮证明
   防御层不是收益来源，但道具口径/首领形态/幻影斩杀/先手值这些修正让标签本身更接近真实结算。
   在此之前不要再拿"自对弈胜率"当唯一验收口径。
1. **陪练要多样**：给评估/训练加陪练池（防御型、应对型、meta 队、规则 agent 变体）——§4e 的
   粗糙防御对手已经能打穿出厂专家（0.571），这就是"策略池/league"的具体动机。
   注意：训练门控现在是**固定阵容套件 + 逐局种子**（§4f-②-3），换套件要显式换
   `ROCO_EVAL_ROSTER_SEED`，别再让它每轮随机漂移。
2. **应对层做准**：22.5% 的决策点存在应对机会，但粗暴实现（按信念挑 counter 技）只有 0.475 →
   先把"预测对手类别"的特征重做（§4b：现特征里只有"我能斩杀它/它被 tick 死"有效）。
3. **心力管理**：1 心时的决策占 9.5%、必死交换占 1.0%——窗口不大，但职业复盘把它当铁律
   （"叠 5 层中毒值不了 1 心"）。排在应对层之后。
4. **估值换成搜索式**（MCTS rollout）——单回合解析估值压不过社区阈值。
5. 待用户判断：§3-3 的"被应对方额外吃一次基础伤害"是否符合线上口径。
