## 2. 抓取与对账方法

- nrc 的条目页只有 `{{特性}}` / `{{技能}}` 一个模板调用，**数据全在 Lua 模块里**：
  `模块:Pets/data/Skills`（824 条：特性 245 / 攻击 358 / 状态 167 / 防御 54）、`Catalog`（621 精灵）、
  `Learnsets`（311 学习表）、`Index`、`Terms`。用 `action=parse&prop=wikitext` 一次取回全量，
  本地 `.zcode/tmp/nrc_lua_parse.py` 解析 Lua 表字面量；所有请求带指数退避（429/567）。
- 对账分三层：
  1. **字段级**：技能 `element`（`武系`→`武`）、`energy_cost`、`power`、`skill_type`（`攻击`+`damage_class`→`物攻`/`魔攻`）、精灵六维/特性/学习表；
  2. **文本级**：描述先归一化（去 `✦` 前缀、标点、全半角），再按「数字多重集是否相同」分为
     **数值差异**（真矛盾）与**措辞差异**；
  3. **集合级**：仅 nrc 有 / 仅本地有。
- id 空间：本地 `id` 沿用 rocom 时期编号（特性 20001–20218、技能 10001–11035），**不迁移**；
  新增条目直接取 nrc `game_id`（特性 200\*\*\*–280\*\*\*、技能 7\*\*\*\*\*\*，与本地空间无冲突）。

### 5.1 已补齐的三条（引擎改动）

| 条目 | 实现 |
|------|------|
| 变形活画「速度+5」 | 新增 `speed_flat` 点数通道（1 点 = 1 点；与 `stat_stage{speed}` 的 10 点/步、`mult_mod{attr:speed}` 的百分比三通道并存），`effective_stat("speed")` 与快照 `speed_self/speed_opp` 口径统一为 `round((base + 步数×10 + 点数) × (1+百分比))`；顺带修正该特性 `power_mult` 的「总量」语义（原实现会把威力倍率写成 2+0.1n） |
| 陨落「回合末效果不会触发」 | 新增 flag `turn_end_block`：任意一方场上精灵携带时，本回合末 `SkillResolver.turn_end()`、其 `extra_turn_end` 额外触发、`turn_end` 观察者、`post_abnormal_tick` 通知全部跳过（ttl 衰减/延迟队列等记账不受影响） |
| 齐鸣「己方精灵携带的虫系技能获得巧变：虫鸣」 | `morph`/`element_convert`/`grant_choice` 的 `affects` 新增 `"team"`：授予者所在队伍**全体（含场下）**的命中技能按需求值获得机制；授予声明用 `scope:"persistent"` 以便授予者下场后队友仍持有巧变。同时补齐第 1 句「自己携带的虫鸣威力+20」 |

顺带修正：`morph` 的 `category` spec dict 在编译期被 `str()` 化（IR_GUIDE 早已承诺 dict 形式），导致 `{"name": "虫鸣"}` 之类的池永远失效——现已保留 dict。

另外把「速度+N 点」但写成 `mult_mod{attr:speed}` 百分比通道的数据纠正到 `speed_flat`：啮合传递(+30)、嘲弄(+70)、快速移动(+160/+80)、流沙统治者(+50)（原实现会算成 `base×(1+30)` 这类荒谬值）；「攻防速+N%」类（最好的伙伴 20%、虫群突袭 15%）保持在百分比通道。
