## 1. 天梯环境（打什么、怕什么）

**天梯两种模式**（[996，2026-01]）：

- **单精灵 1v1**：匹配前锁定一只，属性克制权重极高，"运气匹配"成分大。
- **多精灵轮战（我们复刻的口径）**：满编 6v6，开局不知道对方首发，"可通过主动替换实现动态
  战术调整"；换人时机、技能衔接节奏、状态控制优先级共同决定胜负。

**顶尖梯队**（[smzdm 周报，2026-04，转自抖音创作者]）：

| 档位 | 体系 | 核心机制 |
|---|---|---|
| Top1 | 风降闪击翼王队 | 开天鹅拿强化传递推队；中期用水刃抓状态 |
| Top2 | 落王闪击翼王队 | 用速度差打高速闪击；辅助位负责"倾泻" |
| Top3 | 古龙红队 | 古龙复活特性 → 无死亡压力；反复入场挂减益 |

**基石与常青**：狼王体系（使用率最高、操作简单，新手首选），沙豹 / 第五队 / 雪天 / 雷豹 / 毒队。

**S2 赛季三套 T0**（[搜狐，2026-06，**AI 生成内容**]）：

1. **电鹿轮转队**（双核 + 四联防，叠属性永动）：爵士鹿 / 巨鼓象叠被动，其余四只专职
   联防抗伤、**清除敌方强化**、**消耗对手能量条**。
2. **治疗反伤消耗队**：把"自身受治疗"转化为"敌方全体掉血"，磨死站桩队。
3. **星陨印记爆发队**：快速叠印记层数后集体引爆，专克慢速防守。

**版本强势机制清单**（V3 要能识别的）：印记叠层引爆、中毒叠层、冻结控场、被动永久叠属性、
复活/自返场、强化传递、退化。

## 3. 顺带查出来的一件事：IR 语料让"按效果找技能"的规则全部失效

技能 JSON 的 `effects[]` 是 **IR（op 形式）**，而 `Skill.effects`（旧 `kind` 形式）对 IR 技能
是**空的**（`Skill.load` 静默跳过没有 `kind` 的条目）。实测：

```python
Skill.load(json.load(open("data/skills/泥浆铠甲.json")))  # .effects == [] （空）
battle._get_skill_record("泥浆铠甲").effects              # 3 个 StatStageOp/MultModOp
```

于是任何 `for e in skill.effects if e.kind == ...` 的规则都是**死代码**——
`RuleAgentV2` 的"强化推队"（`e.kind == 'stat'`）与规划层候选排序里的
`20.0 * len(skill.effects)`（恒为 0）都受影响。

新增的 `backend/sim/skill_ir.py` 提供只读画像（`dispel` / `energize(delta<0)` /
`power_mod(energy_cost)` / `stat_stage(steps)` / `interrupt` / `abnormal` / `mark` 全部按
**类型字段**读），规则层不再按技能名写死。注意分支语义：`when/else` 是二选一
（剧毒 常态 3 层 / 应对成功 8 层），所以同族取最大值而不是相加。

## 4. V3 的同局配对 A/B（V3 vs V2，同一阵容同一随机数，交换执 A/B）

工具：`native/tools/eval_expert_change.py --ab v3`（成对协议，CI 下界 > 0.5 才算有效）。
**这一版是改着测出来的**，把弯路也留着：

| 版本 | 改动 | 200 局结果（决出局） |
|---|---|---|
| v3 第 1 版 | 清强化/能量压制/叠层/轮转做成**硬优先级**，插在规划层前面 | **0.421**（61胜–84负）✗ |
| v3 第 2 版 | 上面四条改成候选权重，由规划层裁决 | 0.465（74–85） |
| v3 第 3 版 | 候选**只裁剪功能技**（低伤攻击也一律进候选）；换人候选分数加上限 | 0.486（72–76） |
| v3 第 4 版（当前出厂） | 防御规则默认关（尊重 V2 的 -4.3 点实测）；读牌只用于开窗 | 0.505 [0.481,0.530]（**2000 局 × 2 seed**：819胜 / 802负 / 379平） |

**结论（如实）**：V3 与 V2 **打平**——2000 局同局配对 0.505、CI 含 0.5（平均 31.0 回合，
1829 s）。也就是说：把社区攻略的战术层按"候选 + 情境权重"接进规划层，
**既不涨棋也不掉棋**；真正的收益是"决策过程可解释、可按规则审计"，
以及顺手修掉了"按 `Skill.effects` 写规则 = 死代码"这一类 bug（见 §3）。

**教训（值得留档）**：

1. 手写规则抢在规划层前面，会把实测 +17 点的搜索压掉（0.505 → 0.421 那一档）。
   攻略意图做成"候选 + 情境权重"比做成"硬优先级"稳得多。
2. 候选**按总分取前 N** 会静默把低伤攻击挤出去 —— 规划层于是失去"这回合打输出"这个
   选项。攻击技应一律进候选，只裁剪功能技。
3. 决策层的改动在这个项目里天花板很低：`plan` +17 点、`status_counter` +1.7、
   `defend` -4.3、`EV` -2.4、本版攻略层 ±0。想涨棋得往"搜索深度 / 值函数质量 /
   教师质量"上找（见 `TRAINING.md` §9 与本次自博弈阶段审计）。
